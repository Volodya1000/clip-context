# clip-context

**Одна команда, чтобы собрать нужные файлы проекта в контекст для ИИ.**

Небольшая CLI-программа на Rust. Собирает воспроизводимый контекст локального проекта или файлов на удалённом сервере по SSH. Можно вывести код, посмотреть дерево проекта или скопировать результат в буфер обмена.

[English](README.md) · **Русский**

## Установка

Готовые версии для Windows и Linux публикуются в [GitHub Releases](https://github.com/Volodya1000/clip-context/releases) по тегам.

- **Windows:** архив ZIP для x86_64 и установщик PowerShell с добавлением команды в пользовательский PATH.
- **Linux:** пакет `.deb` или архив `.tar.gz` для x86_64 с проверкой контрольной суммы.

Подробности: [установка на русском](docs/installation.ru.md) ([English](docs/installation.md)). CI собирает пакеты при PR, но скачивание готового бинарника возможно после публикации релиза. Для сборки из исходного кода нужен **Rust 1.85+**:

```sh
git clone https://github.com/Volodya1000/clip-context.git
cd clip-context
cargo install --locked --path .
```

```sh
cpctx -s .                         # Полный контекст в терминал
cpctx -c . --format compact        # Компактный контекст в буфер обмена
cpctx -t .                         # Только дерево файлов
```

`-s` выводит контекст в stdout; `-c` копирует в **локальный** буфер, не печатая исходный код; `-t` показывает пути, не читая содержимое исходных файлов.

## Выбор файлов

```sh
cpctx -s . --ext rs --ext toml      # Только Rust и TOML
cpctx -s . --exclude-dir generated # Исключить каталог на любой глубине
cpctx -c . --profile backend       # Применить готовый профиль
```

Создай `.cpctx.toml` в корне проекта:

```toml
[profiles.backend]
extensions = ["rs", "toml"]
exclude_directories = ["generated"]

[profiles.docs]
extensions = ["md"]
```

Запуск: `cpctx -s . --profile docs`. Другой конфигурационный файл: `--config settings/profiles.toml --profile docs`. Параметр `--ext` **заменяет** список расширений из профиля, `--exclude-dir` **дополняет** список исключений. Продолжают действовать вложенные `.gitignore`, исключения скрытых путей и служебных каталогов.

## Формат и объём контекста

`--format compact` сохраняет все выбранные файлы, но убирает повторяющееся дерево. По умолчанию `--format full` включает дерево. Режим `-t` всегда выводит только дерево.

После успешного выполнения программа кратко сообщает **в stderr**:

```text
Context: 12.4 KiB (12700 bytes) | ~3175 tokens (estimated)
```

Размер относится ко **всему готовому UTF-8-тексту**, а не к потреблению оперативной памяти. Число токенов приблизительное: `ceil(bytes / 4)`, без токенизатора конкретной модели. Статистика и сообщения об ошибках не попадают в stdout и буфер обмена.

`--max-bytes N` (по умолчанию **262144**) и `--max-estimated-tokens N` (по умолчанию **32000**) ограничивают **готовый вывод**, включая пути, Markdown-разметку и дерево, если оно присутствует. Действует более строгий лимит; при превышении ничего не выводится и не копируется.

```sh
cpctx -s . --format compact --max-estimated-tokens 8000 > context.md
```

## Работа по SSH

Установить `cpctx` достаточно **на клиентском компьютере**. На удалённом POSIX-сервере нужны доступ по SSH, оболочка и `tar`:

```sh
cpctx -s /srv/project --ssh dev@server
cpctx -c /srv/project --ssh dev@server --format compact
```

Указанный путь находится на сервере, но буфер обмена используется **локальный**. Проверка ключей сервера выполняется стандартным SSH-клиентом. Максимум передаваемого архива: **16 МиБ**. Фильтры применяются после скачивания, поэтому большой репозиторий может превысить лимит передачи.

## Буфер обмена

- **Windows:** Windows PowerShell с `Set-Clipboard`.
- **Linux / Wayland:** `wl-copy` из пакета `wl-clipboard`.
- **Linux / X11:** `xclip` либо `xsel`.

Для копирования требуется графическая сессия. На сервере без графического окружения используй `cpctx -s` с перенаправлением stdout в файл.

## Безопасность и ограничения

Программа блокирует экспорт некоторых известных ключей и токенов, но **не гарантирует обнаружение всех секретов**. Проверяй контекст перед передачей конфиденциальных проектов. Режим дерева показывает только пути и не читает исходный код. SSH-архив извлекается во временный каталог с проверкой путей и запретом создания ссылок. Ограничение готового контекста и ограничение передачи архива по SSH независимы.

## Справочник команд

`cpctx --help` выводит краткую справку на английском, `cpctx --help-full` открывает подробную справку.

```text
cpctx -s PATH [OPTIONS]    Вывести исходный код (по умолчанию full)
cpctx -t PATH [OPTIONS]    Только дерево файлов
cpctx -c PATH [OPTIONS]    Скопировать в локальный буфер обмена

--format full|compact      Формат Markdown
--ext EXT                  Разрешённое расширение (можно повторять)
--exclude-dir NAME         Исключить каталог (можно повторять)
--profile NAME             Профиль из .cpctx.toml
--config FILE              Другой файл профилей (вместе с --profile)
--ssh USER@HOST            Получить проект по SSH
--max-bytes N              Максимум байтов готового UTF-8-текста
--max-estimated-tokens N   Максимум приблизительных токенов готового вывода
-h, --help                 Краткая справка
--help-full                Подробная справка
-V, --version              Версия
```

Для разработки: `cargo test --locked --all-targets --all-features`. Правила оформления PR и CI см. в [CONTRIBUTING.md](CONTRIBUTING.md).
